# Plan-gate experiment — 2026-10-01..02

Question: how much does plan-eval → re-plan → re-eval buy? Three arms on `PIPELINE_PLAN_GATE`
(`full` | `single` | `none`), then a fourth (`annotate`: eval once, carry `Revise` into execute as
binding amendments, no re-plan). Fixed 6-issue calib slate (A, D, B×4), lean profile, Sonnet
session, Opus executor. Artifacts: `docs/retros/calib/2026-10-0{1,2}T*-plan-gate-*.txt`.

Findings
- plan-eval ≈ 14% of tokens; pr-eval ≈ 40% (16 dispatches / 6 issues) — the bigger lever.
- No accuracy loss across arms on this slate; token deltas within run-to-run noise.
- Wall variance is API latency by hour (serial-B executes 8/11 vs 14/17 min on identical arms), not arm-specific.
- `annotate` removes the re-plan + re-eval dispatches (two Opus agents, ~10 min critical path per Revise)
  and keeps the evaluator's written catch; five carried amendments merged clean. `**Scope:** structural` never fired.
- Output tokens are ~1% of total (run 18: 0.8M of 80.2M; cache_read 103.5M) — cost is context × turns.
